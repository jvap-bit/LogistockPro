LogiStock PRO

Documentação atualizada para a versão que reúne o novo site institucional da LogiStock e o sistema operacional integrado em HTML, CSS, JavaScript, Node.js e SQLite. O antigo aplicativo desktop Python deixa de ser a arquitetura principal desta documentação.

HTML5CSS3JavaScriptNode.js ≥ 22.13SQLiteQR Code
Visão Geral

Introdução

O projeto atual possui dois ambientes complementares. O primeiro é o site institucional, responsável por login visual, apresentação da empresa, cadastro, rastreamento, avaliação, acessibilidade e conteúdo público. O segundo é o LogiStock Sistema Integrado, executado por um servidor Node.js e responsável pela operação real de ordens de produção, usuários, sessões, Kanban, logística, QR Code e histórico.

Principal mudança: a versão integrada não depende do antigo programa Python/CustomTkinter para operar. O núcleo operacional agora roda no navegador, com um servidor Node.js compartilhando o mesmo banco SQLite entre as contas.

Site Institucional

Novo site da LogiStock

O site continua separado do painel operacional e apresenta a identidade visual da LogiStock. A entrada principal está em index.html, com formulário de e-mail e senha e redirecionamento para web/pages/inicio.html. Nesta camada, o nome exibido após o login é derivado do e-mail e salvo em localStorage.

Importante: o login da raiz do site é uma experiência de front-end. A autenticação protegida por senha, hash, sessão e banco de usuários está implementada no sistema integrado Node.js.

Sistema Integrado

Servidor Node.js e API

O arquivo server.js é o núcleo do sistema operacional. Ele cria um servidor HTTP, serve os arquivos da pasta public, abre o SQLite com node:sqlite, gera QR Codes e disponibiliza rotas de API.

RotaMétodoFunção
/api/registerPOSTCadastra usuário e perfil.
/api/loginPOSTValida credenciais e cria sessão.
/api/logoutPOSTEncerra a sessão atual.
/api/meGETRetorna a conta autenticada.
/api/trackGETConsulta uma OP pelo número.
/api/ordersGET / POSTLista ou cria ordens.
/api/orders/:idPATCH / DELETEAtualiza status ou remove uma OP conforme permissão.
/api/orders/:id/qrGETGera o QR de consulta da ordem.
/api/logsGETConsulta o histórico de ações.
/documentoGETPágina pública protegida por token aleatório do QR.
Segurança

Autenticação real

O sistema integrado cadastra contas com e-mail, senha e perfil. A senha não é armazenada em texto simples: o servidor gera um salt aleatório e usa scrypt para produzir password_hash. No login, a comparação usa operação segura de tempo constante.

Após autenticar, o servidor cria um token aleatório, salva somente o hash do token na tabela sessoes e envia ao navegador um cookie HttpOnly com SameSite=Lax. A sessão expira em sete dias.

Senha→Salt + scrypt→Hash no SQLite→Login→Cookie de sessão
Controle de Acesso

Perfis do sistema

PCP

Cria OPs, acompanha o Kanban e avança o fluxo A Fazer → Em Andamento → Qualidade → Finalizado. Pode remover registros permitidos.

Produção

Acompanha as ordens criadas pelo PCP e as etapas produtivas em painel próprio.

Gestão

Visualiza todas as etapas, indicadores por contagem, histórico e pode remover ordens finalizadas/entregues conforme a regra do sistema.

Entregador

Trabalha no painel logístico, consulta OP, lê QR quando o navegador permite e movimenta Finalizado → Em Rota → Entregue.

Produção

Ordens, Kanban e atualização

As ordens são carregadas do SQLite e exibidas pelo app.js. O sistema possui pesquisa por OP/cliente, ordenação e cards com ações condicionadas ao perfil. As telas consultam novamente os dados periodicamente, permitindo que alterações feitas em uma conta apareçam nas outras.

A Fazer→Em Andamento→Qualidade→Finalizado→Em Rota→Entregue

A atualização automática ocorre a cada 4 segundos. Portanto, a versão atual usa sincronização por consultas periódicas (polling), e não WebSocket.

Dados de uma OP

Número, produto, quantidade, cliente, rua, número/casa, bairro, CEP, prioridade, status, descrição e token de QR. O número da OP é validado para evitar novos registros duplicados.

Logística

PDF, QR Code e celular

O botão PDF + QR abre um comprovante de impressão no navegador. O QR não armazena todo o documento: ele contém um link para /documento com um token aleatório associado à OP.

OP no SQLite→Token aleatório→Link /documento→QR Code→Celular

A página aberta no celular mostra OP, produto, quantidade, cliente, endereço, prioridade e status atual. Ela também oferece acesso ao sistema para o entregador. O comprovante é operacional e não substitui nota fiscal eletrônica.

Atenção: quem possuir o QR/link consegue consultar os dados do comprovante. O PDF não deve ser compartilhado fora da equipe responsável.
Persistência

Banco SQLite

O banco está em LogiStock_sistema_integrado/data/producao.db. O servidor ativa WAL, timeout de banco e chaves estrangeiras.

TabelaResponsabilidadeCampos principais
pedidosOrdens de produção e logística.numero, produto, quantidade, cliente, endereço, prioridade, status, descricao, qr_token.
usuariosContas dos quatro perfis.email, perfil, data_cadastro, salt, password_hash.
logsAuditoria das ações.data_hora, acao.
sessoesSessões autenticadas.token_hash, usuario_id, expira_em.

Os arquivos producao.db-wal e producao.db-shm são auxiliares do modo WAL do SQLite e não devem ser editados manualmente.

Execução

Instalação do sistema integrado

O sistema requer Node.js 22.13 ou superior. Dentro da pasta LogiStock_sistema_integrado, execute:

npm install
npm start

O script npm start executa node server.js. Por padrão, o painel fica disponível na porta 3000.

Dependência NPM principal: qrcode ^1.5.4. O SQLite é utilizado por meio do módulo node:sqlite da versão compatível do Node.js.
Rede Local

QR Code acessível pelo celular

Para o celular abrir o QR, ele precisa alcançar o computador que executa o servidor. Computador e celular devem estar na mesma rede, ou o sistema deve possuir um endereço HTTP/HTTPS acessível.

No Windows/PowerShell, antes de iniciar o servidor, pode ser definido:

$env:APP_BASE_URL = "http://192.168.1.10:3000"
npm start

O IP acima é apenas um exemplo: deve ser substituído pelo IPv4 real do computador. Antes de gerar o comprovante, teste esse mesmo endereço no navegador do celular e permita o Node.js na rede privada do Firewall do Windows.

Estado Atual

Limites e melhorias futuras

  • O cálculo de frete continua simplificado em peso × R$ 12,50; os CEPs não calculam distância real.
  • A exportação da versão web é voltada a CSV compatível com Excel; o comprovante PDF usa a impressão do navegador.
  • A leitura automática de QR pela câmera depende de BarcodeDetector, suporte do navegador e permissão de câmera; a digitação manual da OP continua disponível.
  • A sincronização entre contas ocorre por atualização periódica de 4 segundos, não por WebSocket.
  • O cadastro de perfis é adequado para demonstração/rede de confiança; uma implantação pública deve adicionar administração de contas, HTTPS e políticas de segurança mais rígidas.
  • O login do site institucional e o login do sistema integrado são camadas diferentes; uma evolução futura pode unificar completamente a autenticação entre os dois ambientes.
Backup: para preservar usuários, OPs, logs e tokens, mantenha cópia segura do arquivo data/producao.db com o servidor parado ou usando um procedimento apropriado de backup SQLite.
