Visão Geral

Introdução

O LogiStock Pro é um sistema de gestão logística dividido em dois ambientes: um site público institucional (HTML/CSS/JS) com páginas de apresentação, rastreamento de pedidos e chatbot IA integrado; e um aplicativo desktop em Python com interface CustomTkinter que gerencia ordens de produção via painel Kanban, exportação de relatórios e fluxo de entrega.

⚠️
Requisito de execução: O app desktop requer Python 3.x instalado. Na primeira execução, main.py instala automaticamente as dependências (customtkinter, pandas, openpyxl, requests, reportlab).
🌐
Para o site: O fetch() de componentes requer protocolo HTTP. Use Live Server (VS Code) ou qualquer servidor local — abrir direto no navegador com file:// não funciona.

Segurança

Autenticação

O app desktop usa um sistema de login simples por perfil de acesso. Não há senha salva em banco — o usuário escolhe o perfil no dropdown e entra. O logout limpa a tela e retorna à tela de login.

EtapaFunçãoO que acontece
1. Logintela_login()Card centralizado com campos usuário, senha e seletor de perfil
2. Entradalogin_logic()Valida se os campos estão preenchidos. Redireciona por perfil
3. Proteçãotela_principal()Se perfil == Entregador, redireciona para tela_entrega_v2()
4. Logouttrocar_conta()Destroi todos os widgets e recria a tela de login
5. Encerrardesligar_sistema()Confirmação → self.destroy() + sys.exit()
💡
Site web: O site usa localStorage para persistir o nome do perfil exibido no header e no menu lateral. O modal de perfil (perfil.js) permite editar nome, e-mail e foto de perfil salvos localmente.

Fluxo de Status

O status das ordens segue um fluxo linear no Kanban para PCP/Produção. A partir do "Finalizado", o entregador pode mover para "Em Rota" e depois "Entregue".

Fluxo de status em logic_utils.py 
# Fluxo Kanban (PCP avança)
fluxo = ["A Fazer", "Em Andamento", "Qualidade", "Finalizado"]

# Fluxo do entregador (após Finalizado)
"Finalizado"  →  "Em Rota"  →  "Entregue"

# No Kanban, todos os status de entrega aparecem na coluna "Finalizado"
if status_db in ["Finalizado", "Em Rota", "Entregue"]:
    status_destino = "Finalizado"

Formulário

Cadastro de Ordens de Produção

Disponível apenas para o perfil PCP. Abre como janela CTkToplevel com scroll interno organizado em seções.

  • 1
    Dados da Ordem: Número da OP, quantidade (lado a lado) e nome do produto. Todos obrigatórios.
  • 2
    Dados do Cliente: Razão social ou nome completo. Campo obrigatório.
  • 3
    Endereço via ViaCEP: Ao sair do campo CEP (FocusOut), consulta https://viacep.com.br/ws/{cep}/json/ e preenche rua e bairro automaticamente. Exibe feedback visual (buscando / encontrado / erro).
  • 4
    Prioridade: Botão segmentado Normal / Urgente. Urgente aplica badge vermelho no card do Kanban.
  • 5
    Observações: Campo textbox livre. Salvo na coluna descricao e exibido na janela de detalhes.
  • 6
    Salvar: Validação de campos obrigatórios antes do INSERT. Após salvo, chama atualizar_interface() e fecha a janela.

Painel do Entregador

Interface simplificada e exclusiva para o perfil Entregador. Sem menu lateral, sem Kanban — apenas as ordens prontas para entrega.

# Busca pedidos prontos ou em trânsito
cur.execute("""
  SELECT id, numero, produto, cliente, status, bairro
  FROM pedidos
  WHERE status IN ('Finalizado', 'Em Rota', 'Entregue')
""")

Funcionalidades

Ferramentas do Sistema

Acessíveis pelo menu lateral (☰) na tela principal. Cada ferramenta abre em um container sobreposto que substitui o Kanban.

Cálculo de Frete

Calculadora simplificada com CEP de origem, CEP de destino e peso em kg. O cálculo usa uma fórmula base de peso × R$ 12,50 — placeholder para integração futura com API de transportadoras.

Rastreamento

Consulta pelo número da OP no banco local. Traduz o status técnico para linguagem do cliente: Finalizado → "Pronto para Coleta", Em Rota → "Saiu para Entrega", Entregue → "Entregue ao Cliente". Cor muda conforme status.

Tabela de Pedidos

Exibição tabular com ttk.Treeview mostrando todas as ordens: ID, Nº OP, Produto, Qtd, Cliente, Bairro e Status. Botão de exportação para Excel integrado.

Histórico de Logs / Auditoria

Exibe todos os registros da tabela logs em ordem decrescente, com data/hora e descrição da ação. Interface tipo terminal (Consolas 12px).

Relatórios

Exportação de Dados

Excel (.xlsx)

Exporta todos os pedidos da tabela pedidos para Excel. O arquivo é salvo em arquivos_exportados/Relatorio_Pedidos.xlsx e a pasta é aberta automaticamente (os.startfile()).

logic_utils.py — exportar_excel() 
conn = sqlite3.connect("producao.db")
df = pd.read_sql_query("SELECT * FROM pedidos", conn)
conn.close()

data_str = datetime.now().strftime('%d%m%Y_%H%M')
nome_arquivo = f"Relatorio_{data_str}.xlsx"
df.to_excel(caminho_final, index=False)

PDF de Ordem de Produção

Gera um PDF individual para cada OP com ReportLab. O nome inclui um timestamp Unix para evitar conflito de arquivos (OP_{numero}_{timestamp}.pdf). Aguarda 0,5s antes de abrir para garantir que o sistema operacional processe o arquivo.

📁
Pasta de exportação: Todos os arquivos gerados (.xlsx e .pdf) são salvos em arquivos_exportados/, criada automaticamente se não existir. Os arquivos incluídos no repositório são exemplos de saída.
